Engineering Process
1. Read first
read_file on exact lines before touching anything. Never edit blind.
2. Minimal change

3. Validate locally
Brace balance, zero corruption markers, 25/25 function presence — PowerShell.
4. Commit
Semantic message on UM_GIT-Branch1.
5. Deploy
Merge to main, push both remotes, poll Pages API until built.

USOBT vs USOBX
USOBT
SAP-delivered proposed auth objects per T-Code (OKFLAG = Y). Used as reference for SU24 proposals. Loaded in the T-Code Analyzer as "SAP-Proposed".

USOBX
SAP-delivered active auth objects (OKFLAG = X). Actually checked at runtime. Loaded as "SAP-Active".
DPC_EXT Architecture
OData services inherit from a base Data Provider class. The DPC_EXT class overrides operations:

CREATE_ENTITY • GET_ENTITY
GET_ENTITYSET • UPDATE_ENTITY
DELETE_ENTITY • EXECUTE_ACTION

Each override must add an AUTHORITY-CHECK before any data operation.
Clean Core (S/4HANA)
No modifications to SAP standard objects. Auth remediation must use:

Released APIs only
Extension points (BAdI)
Custom namespace (Z/Y)
No direct SE16 edits
Upgrade-stable patterns

The tool flags Clean Core non-compliance on every finding card.
