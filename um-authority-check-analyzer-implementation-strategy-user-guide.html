01Executive Summary

The UM_Authority-Check-Analyzer is a governed SAP Authorization Diagnostic Intelligence tool developed by Utsav Mukherjee under the IBM ICA (Intelligent Code Assistant) program. It provides SAP security teams with a fast, interactive, browser-based interface to detect, classify, and remediate authorization defects across ABAP programs, SU24 transaction proposals, and OData/Fiori service layers.

The tool operates entirely in the browser — no data is sent to any server, no SAP system connection is established, and no changes are made automatically. All findings are diagnostic only and require human approval from SAP Security before any correction is applied.

CURRENTLY LIVE Hosted permanently on GitHub Pages CDN. Available 24×7 globally. No login, no installation, no laptop dependency.
URL: https://ica-bob.github.io/um-authority-check-analyzer/
02Tool Overview & Purpose

What It Does

The tool guides a SAP security analyst or developer through a structured, conversational diagnostic workflow. The analyst provides context (SAP system, release, transaction, business action, evidence), and the tool runs one or more of three specialized analyzers to produce structured findings with severity ratings, evidence, impact assessment, and code-level remediation guidance.

Why It Was Built

  • SAP authorization defects are frequently missed during code reviews due to the complexity of AUTHORITY-CHECK patterns
  • SU24 proposal gaps cause role generation failures that are hard to diagnose without specialized knowledge
  • OData/Fiori services are often deployed without DPC_EXT authorization checks, creating critical exposure
  • IBM ICA and IBM Bob needed a governed, audit-trail-enabled interface aligned with MCP Gateway standards

  • Distribute this document to SAP Security, SAP Development, and IBM ICA teams
  • Conduct a 30-minute walkthrough session using the Combined Review mode

Full Workflow — 8 Steps

1

Select Analysis Type

Type check or click a quick start button. Select ABAP, SU24, ODATA, or COMBINED.

2

Enter SAP System

Type the system: S/4HANA, S/4HANA Private Edition, or ERP 6.0 EhP8.

3

Enter SAP Release

Type the release: 2023, 2022, 1909, 1809 etc.

4

Enter Transaction / Service

Type a SAP transaction code (ME22N, FB01, VA01) or OData service name (ZVENDOR_SRV). Known authorization objects are displayed automatically for recognised transactions.

5

Describe the Business Action

E.g. Change purchase order with purchasing org restriction or Post FI document with company code control.

6

Describe Evidence / Concern

Examples: Program calls CHANGE_DOCUMENT without AUTHORITY-CHECK · M_BEST_EKO missing from proposal · sy-subrc is not evaluated after the check · UPDATE_ENTITY has no authorization check in DPC_EXT

PRIVACY PROTOCOL ACTIVEPasswords, tokens, secrets, and email addresses in evidence are automatically masked before processing.
7

Enter Change Ticket

Enter your ServiceNow / JIRA / SAP change ticket reference (e.g. CHG-2026-00123). Type skip if not available.

8

Review & Confirm

A confirmation summary is shown with all entered details. Click PROCEED to run analysis, MODIFY to change any field, or CANCEL to discard.

After Analysis — Next Steps

  1. Route findings to SAP Security for review and approval
  2. SAP Development applies approved corrections
  3. Changes follow the normal SAP transport process
  4. Retest using positive and negative scenarios from the finding card
  5. Close the finding with the approved change ticket reference
HUMAN APPROVAL MANDATORYALL findings are diagnostic and read-only. The tool NEVER modifies any SAP system automatically. Every correction MUST be reviewed and approved by SAP Security before being applied.
