Pattern engines

The ABAP and OData engines read what you paste. They need no pre-loaded object list, so they work equally on standard code, Z-namespace code and anything in between.

Your own data

Engine 1

ABAP Code Scanner

Paste a complete unit — METHOD … ENDMETHOD, FORM … ENDFORM or FUNCTION … ENDFUNCTION. Block structure is how reachability is decided, so unit boundaries matter.

Context
Nothing typed here leaves your browser. Lines beginning with # are ignored.
Engine 2

T-Code Analyzer

One transaction per line: TCODE | dialog·report·parameter | PROGRAM | AUTH GROUP. Only the transaction is required.

Engine 3

Fiori Application Analyzer

One app per line: APP ID | type | ODATA SERVICE | BUSINESS CATALOG | TECHNICAL CATALOG | note. Take the technical mapping from the SAP Fiori apps reference library — this tool will not guess it.

Engine 4

Web Dynpro Analyzer

One application per line: APPLICATION | COMPONENT | SICF PATH | S_SERVICE evidence | note.

SRV_NAME is a hash. Derive it by adding the application to a role menu and letting PFCG generate S_SERVICE, or read it with report RSCSAUTH. A hand-typed value almost never matches, and the role then authorises nothing while looking correct.
Engine 5

OData Service Analyzer

One operation per line: METHOD | ENTITY SET | note. Say in the note whether a backend check is present.
